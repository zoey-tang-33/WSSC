# WSSC: Wavelet-Guided Semantic Signal Compensation for Inversion-Free Image Editing

## Introduction

**WSSC** (Wavelet-guided Semantic Signal Compensation) is a training-free method that augments inversion-free image editing on rectified flow models (e.g., FLUX.1-dev). It requires **no DDIM inversion** of the source image — instead, it directly integrates an ODE that transports the source latent toward the target prompt.

### Motivation: Semantic Indistinguishability in the High-Noise Regime

Inversion-free editing methods estimate a geometric editing signal `Δv = v(x_tar, t; e_tar) − v(x_src, t; e_src)` between source and target trajectories. While this signal is non-zero during the high-noise phase, it provides only **weak and unreliable semantic directionality** — the dominant manifold-seeking flow (transporting noise toward the data manifold) outweighs the subtle text-conditioned direction. As a result, the target latent accumulates insufficient directional momentum for global attribute changes (e.g., overall color shifts). By the time the noise level decreases enough for the prompt to exert stronger control, the global layout and color composition are already fixed.

### Method Overview

WSSC introduces three key components:

1. **Same-Point Semantic Probing**: Evaluate both source and target prompts at the *same* latent point `x_src_t`, obtaining a **semantic editing signal**:
   ```
   v_sem(x_src_t, t) = v_θ(x_src_t, t; e_tar) − v_θ(x_src_t, t; e_src)
   ```
   Since both evaluations share the same input, this removes the geometric confound from evaluating at distinct latent points. The source-prompt velocity is already available, so this costs only **+1 extra forward pass per timestep**.

2. **Wavelet Low-Frequency Extraction**: Directly injecting `v_sem` can introduce high-frequency perturbations from the random forward noise. We apply a multi-level 2D Haar wavelet decomposition, zero out all detail sub-bands, and reconstruct — retaining only the spatially coherent low-frequency component:
   ```
   v_low = LF(v_sem)
   ```
   where `LF(·)` performs L-level Haar DWT, zeroes detail coefficients, and applies inverse DWT.

3. **Time-Modulated Compensation**: The low-frequency signal is injected with a quadratic time weight `w(t) = λ·t²`, yielding the modified ODE update:
   ```
   x_{t_{i+1}} = x_{t_i} + (t_{i+1} − t_i) · [Δv_{t_i} + λ·t_i² · LF(v_sem(x_src_t, t_i))]
   ```
   - At `t → 1` (high noise): weight ≈ λ, maximally activating compensation where `Δv` is least informative.
   - At `t → 0` (low noise): weight → 0, reducing to the baseline update and preserving fine-detail fidelity.
   - Setting `λ = 0` recovers the baseline exactly.

An optional binary mask `M` can restrict the edit signal to a specific spatial region.

```bash
conda create -n wssc python=3.10
conda activate wssc
pip install -r requirements.txt
```

## Data and Model Setup

1. **FLUX.1-dev model**: Download from [black-forest-labs/FLUX.1-dev](https://huggingface.co/black-forest-labs/FLUX.1-dev) and place it under `./models/FLUX.1-dev/`.

2. **PIE-Bench dataset**: Download from the [PIE-Bench repository](https://github.com/wyf0912/PIE-Bench). Place the `annotation_images/` folder and `mapping_file.json` under `./data/PIE-Bench/`.

3. **Editing masks**: Generate from `mapping_file.json` (see [Mask Generation](#mask-generation) below).

Expected directory structure:
```
WSSC/

├── data/

```

## Mask Generation

PIE-Bench provides per-image editing masks as **RLE-encoded arrays** inside `mapping_file.json`. Each entry contains a `"mask"` field — a flat list of `[start_index, run_length, ...]` pairs over a 512×512 image. The included `generate_masks.py` script decodes these RLE masks and saves them as grayscale PNGs (white = edit region, black = background), mirroring the PIE-Bench category directory structure.

### Generating masks

```bash
python generate_masks.py \
    --mapping_file ./data/PIE-Bench/mapping_file.json \
    --output_dir ./data/mask
```

This produces 700 mask PNGs under `./data/mask/`:
```
data/mask/
├── 0_random_140/
│   ├── 000000000000.png
│   ├── 000000000001.png
│   └── ...
├── 1_change_object_80/
└── ...
```

### Mask format

- **Size**: 512×512 pixels
- **Mode**: Grayscale (`L`)
- **Values**: `0` (black = background, edit blocked) and `255` (white = edit region, edit allowed)
- **Boundary**: Border pixels are set to white (edit allowed) to avoid annotation errors at image edges, following the original PIE-Bench evaluation protocol

In the WSSC pipeline, the mask restricts where the edit signal `V_delta` propagates. When `use_mask: true` in the config, pixels where the mask is white (value 255) receive the full edit signal, while black pixels (value 0) are protected from changes.

## Usage

### Quick test (5 images)

```bash
python run_wssc.py --device_number 0 --exp_yaml wssc_config_test.yaml
```

### Full benchmark (700 images)

```bash
python run_wssc.py --device_number 0 --exp_yaml wssc_config.yaml
```

```bash
python run_wssc.py --device_number 0 --exp_yaml wssc_config.yaml --model_path /path/to/FLUX.1-dev
```

## Configuration

The experiment YAML file (`wssc_config.yaml`) contains the following parameters:

| Parameter | Symbol | Default | Description |
|---|---|---|---|
| `T_steps` | `N` | `28` | Number of ODE steps |
| `n_avg` | `K` | `1` | Number of noise averaging iterations per step |
| `src_guidance_scale` | — | `3.5` | Guidance scale for source-prompt velocity |
| `tar_guidance_scale` | — | `5.5` | Guidance scale for target-prompt velocity |
| `n_min` | `n_min` | `0` | Final standard-sampling steps (SDEdit-style denoising) |
| `n_max` | `n_max` | `24` | Active editing window (steps processed before n_max from end) |
| `seed` | — | `10` | Random seed |
| `spectral_boost` | `λ` | `3.0` | Semantic compensation strength (0 = no compensation) |
| `n_levels` | `L` | `3` | Haar wavelet decomposition levels |
| `use_mask` | — | `true` | Whether to apply an external editing mask |

**Default settings (FLUX)**: `λ=3.0`, `L=3`, `N=28`, `n_min=0`, `n_max=24`, `src_guidance=3.5`, `tar_guidance=5.5`.
